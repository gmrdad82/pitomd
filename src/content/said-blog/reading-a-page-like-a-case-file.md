A tracker answers one question well: what should move next? But some
mornings the question is different. What happened to this? Why did it come
back? How long has this really been open?

## Columns are the wrong shape for memory

Kanban boards are deliberately amnesiac — a card in "done" looks exactly
like it strolled there in an afternoon, even if it fought its way back from
done three times. The now crowds out the story.

Said and Done. keeps the story. Each chapter is one running record with the
freshest word on top, like a ledger of the desk — every page a line in it,
wearing its status, its dates, and the files it points at.

![The record — every page as one running line, freshest first](/said-and-done/shots/dossier.png)

_The record: pages read as an account instead of a queue. An index drawer
files them alphabetically when you'd rather browse than scroll._

## The case file

Open any page and it opens as a case file. The vitals: what status it's
in, how many times it came back from done, how long it lived, who spoke in
it. The spec trail: every edit to what the page asks. The activity: every
status it passed through. The thread: everything said, by everyone, named.

![A case file — the whole life of one page on a single sheet](/said-and-done/shots/casefile.png)

_ATL-4's case file: born, shipped, reopened, shipped again — with the
agent that fixed it signing its comment._

And the reopens get their own section, called out in red — because a page
that keeps coming back is trying to tell you something, and a queue will
never say it.

## One record, honestly

No one owns a page in Said and Done., so the case file is also how a shared page
stays honest. When you and an agent both worked it, the file shows exactly
who did what, in order, without anyone's memory in the loop.

Deciding and understanding are different jobs. The record does both: pick a
page and move it with a chord, or scroll the account of what happened while
you were away. Same desk, same truth.
