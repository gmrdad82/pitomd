A board answers one question well: what should move next? But some mornings
the question is different. What happened to this? Why did it come back? How
long has this really been open?

## Columns are the wrong shape for memory

Kanban is a deciding instrument. It shows you now: what waits, what moves,
what landed. It is deliberately amnesiac — a card in "done" looks exactly
like it strolled there in an afternoon, even if it fought its way back from
done three times.

So Said and Done. has a second face: the dossier. Same cards, same data, no sync —
one running record with the freshest word on top, like a ledger of the
desk.

![The dossier — every card as one running record, freshest first](/said-and-done/shots/dossier.png)

_The dossier face: the same cards the board carries, read as a record
instead of a queue. An index drawer files them alphabetically when you'd
rather browse than scroll._

## The case file

Click any card in the dossier and it opens as a case file. The vitals: what
state it's in, how many times it came back from done, how long it lived,
who spoke in it. The spec trail: every edit to what the card asks. The
activity: the whole journey between lanes. The thread: everything said, by
everyone, named.

![A case file — the whole life of one card on a single sheet](/said-and-done/shots/casefile.png)

_ATL-4's case file: born, shipped, reopened, shipped again — with the
agent that fixed it signing its comment._

And the reopens get their own section, called out in red — because a card
that keeps coming back is trying to tell you something, and a board will
never say it.

## Two faces, honestly

No one owns a card in Said and Done., so the case file is also how a shared card
stays honest. When you and an agent both worked it, the file shows exactly
who did what, in order, without anyone's memory in the loop.

Deciding and understanding are different jobs. Now they have different
faces — a switch in Settings, and one question at first boot: how should
your work face you?
